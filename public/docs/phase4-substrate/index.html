    Phase 4 · Substrate 区块链开发

    Phase 4 · Substrate 区块链开发

    前置条件

    • 完成 Phase 1 & 2，熟悉 Rust trait、泛型、宏、异步
    • 了解区块链基本概念（区块、交易、共识、账户模型）

    阶段目标

    • 理解 Substrate 的整体架构（Runtime / Host / Node）
    • 掌握 FRAME 框架，能独立编写自定义 pallet
    • 实现一个具有实际功能的链（如数据存证 / 访问控制）
    • 理解 Runtime 升级机制（Wasm 热升级）
    • 为 Phase 3 的 ZKP verifier 集成做准备（on-chain verifier pallet 设计）

    参考资料

    资料 路径 用途
    polkadot-sdk substrate/polkadot-sdk/ 主 SDK，FRAME pallet 实现参考
    polkadot-docs substrate/polkadot-docs/ 官方概念文档，架构说明
    polkadot-cookbook substrate/polkadot-cookbook/ 具体 Recipe，按需查阅

    主题进度

    架构理解

    • Substrate 节点结构（Client / Runtime / Networking）
    • Runtime 的 Wasm 编译与执行模型
    • Extrinsic（交易）生命周期
    • 存储模型（StorageValue / StorageMap / StorageDoubleMap）

    FRAME 框架

    • pallet 宏系统（#[pallet::*]）
    • Config trait 与 Runtime 集成
    • 存储项定义与读写
    • 事件（Event）与错误（Error）
    • Hooks（on_initialize / on_finalize）
    • 权重（Weight）与基准测试（Benchmarking）

    实践项目

    • 数据存证 pallet：链上存储数据哈希，证明数据在某时刻存在
    • 访问控制 pallet：基于角色的数据访问权限管理
    • ZKP Verifier pallet（Phase 3 完成后）：链上验证 Groth16 / halo2 证明

    写作原则

    • 以问题驱动：每篇笔记从"我要解决什么问题"开始，避免脱离实际的纯概念记录
    • 记录宏展开：FRAME 宏是 Substrate 的核心，遇到不理解的宏时用 cargo expand 展开并记录关键部分
    • 版本标注：polkadot-sdk 迭代快，笔记中标注对应的 SDK 版本或 commit
    • 安全意识：数据安全研究背景下，笔记中注意记录 pallet 中可能存在的攻击面（重放攻击、存储溢出、权限绕过等）
